## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:


- [MultiQC](#multiqc) - Aggregate report describing results and QC from the whole pipeline
- [Integration results](#integration-results) - BLAST, mapping, IGV, and dotplots for the assemblies selected by `--integration_dbs`
- [Variant calls](#variant-calls) - Optional DeepVariant and Sniffles2 output
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution



### MultiQC

<details markdown="1">
<summary>Output files</summary>

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

</details>

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

Results generated by MultiQC collate pipeline QC from supported tools e.g. FastQC. The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Integration results

<details markdown="1">
<summary>Output files</summary>

- `<sample>/integration-results/<db_type>/`

</details>

`<db_type>` is one of `primary`, `alternate`, and `combined`. `--integration_dbs` selects which of those directories are produced:

- `all` (default) writes all three.
- `combined` writes only `combined/`.
- `prim_and_alt` writes `primary/` and `alternate/` and does not build the combined database.

### Variant calls

<details markdown="1">
<summary>Output files</summary>

- `<sample>/integration-results/<db_type>/variants/<hit_id>/` — DeepVariant VCF, gVCF, indexes, and bcftools stats when `--call_small_variants` is set
- `<sample>/structural-variants/` — composite reference, Sniffles2 VCF, alignment, bcftools stats, and one IGV HTML when `--call_structural_variants` is set

</details>

`--call_small_variants` runs DeepVariant with the PacBio model on the per-hit minimap2 BAM. The reference is the extracted hit FASTA, so positions are on that window, including the flanks. The same VCF is a track in that hit's IGV HTML after contig names of the form `contig:start-end` are rewritten to `contig_start-end`.

`--call_structural_variants` aligns the sample reads once to the host reference with the plasmid sequence appended. Plasmid contig names are prefixed `plasmid_`. Host contig names are unchanged. Sniffles2 calls structural variants on that alignment. Those calls are not, by themselves, plasmid integration events. The Sniffles VCF is the site list of a separate per-sample IGV HTML. It is not drawn on the per-hit report, because the coordinates do not match.

Both flags default to true. bcftools stats from either caller are collected in the MultiQC report.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://www.nextflow.io/docs/latest/tracing.html) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
